A list reads and writes its query through a **router adapter**: an object with `pathname`, `search`
and `navigate(href, { replace })` — the [`RouterAdapter`](/api/main/router-adapter/) type.
`useQubeeList` finds its adapter in one of two ways.

`<BrowserAdapter>` is for apps without a router: it reads `location` and writes with
`history.pushState` and `replaceState`. Inside React Router, TanStack Router or Next.js, use that
router's adapter instead — [React Router](/setup/react-router/),
[TanStack Router](/setup/tanstack-router/), [Next.js](/setup/next/) — because their router would
not see these navigations.

The three router adapters keep the scroll position when a list navigates: a filter or a page
number that changes should not send the reader back to the top. Each takes `scroll` to hand that
back to its router — `<ReactRouterAdapter scroll>`, or `useNextAdapter({ scroll: true })` for one
list.

The provider hands down the adapter _hook_, not a router value. Only the components that use a
list re-render when the URL changes, never the whole subtree. The nearest provider wins, so a
provider around part of the tree gives that part its own adapter.

## Or pass it to the hook

```tsx
const list = useQubeeList(articleList, useBrowserAdapter());
```

An adapter passed as the second argument wins over the provider. Use it for the one list that must
not follow the rest of the tree. The component still re-renders when the provider's URL changes:
hooks cannot be called conditionally, so the provider's adapter is read either way.

With neither a provider nor an argument, `useQubeeList` throws
[`MissingRouterAdapterError`](/api/main/missing-router-adapter-error/). It never falls back to
browser history by itself: inside a router library, that would leave the router out of step with
the URL.

## Two lists, one URL

Two different lists under one provider that name a URL parameter the same — both `page`, say —
read and write the same value, so paging one pages the other. In development the hook logs a
warning that names both lists and the parameter. Give the param another URL name in one of them:

```ts
page: integerParam('tagPage', { default: 1, min: 1 }),
```

When two lists _should_ share a value — one search box driving two result lists — declare the
param once and use the same object in both definitions. Lists that share a param object do not
warn, and neither does one list used by several components.
