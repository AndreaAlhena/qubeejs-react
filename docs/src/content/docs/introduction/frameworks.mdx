The adapter brings no router and no bundler of its own. Two things change from one setup to the
next: where a shared instance is provided, and which router a URL-driven list writes through. A
router is any object with `navigate(href, { replace })`, `pathname` and `search` — the
`RouterAdapter` type.

the URL do not:

For URL-driven lists without a router library, `useBrowserAdapter()` reads `location` and writes
with `history.pushState` and `replaceState`. Every component that calls it stays in step, through the back and forward buttons too. It observes only its own `navigate` plus Back and
Forward: a `pushState` by other code is not seen until the next `popstate`, so parameters that code
added can be dropped by the next `set()`. When something else also writes the URL, use your
router's adapter.

## Next.js (App Router)

`@qubeejs/react` is marked as a client module, so a Server Component can import its components;
its hooks still run in client components only. Two things remain yours: `QubeeProvider` goes in
your own client component, as below, and `useSearchParams` on a statically rendered route needs a
`<Suspense>` boundary above it, or `next build` fails.

### Server Components import the core

A Server Component never calls the hooks of `@qubeejs/react` — hooks and context exist only in
client components. It imports `@qubeejs/core`, which never imports React: `readListState`,
`buildListRequest` and `buildListHref` all run on the server. See
[Server rendering](/guide/server-rendering/).

## TanStack Router

The adapter ships as the entry point `@qubeejs/react/tanstack-router`: wrap the root route's
outlet in `<TanStackRouterAdapter>`. See the [TanStack Router recipe](/recipes/tanstack-router/).
