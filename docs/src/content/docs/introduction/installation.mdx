Install the adapter together with the core. The core is a peer dependency: you import drivers,
`defineList` and the list params from it directly, so your app owns its version.

<Tabs syncKey="package-manager">
  <TabItem label="npm">

```sh
npm install @qubeejs/react @qubeejs/core
```

  </TabItem>
  <TabItem label="pnpm">

```sh
pnpm add @qubeejs/react @qubeejs/core
```

  </TabItem>
  <TabItem label="yarn">

```sh
yarn add @qubeejs/react @qubeejs/core
```

  </TabItem>
</Tabs>

## Requirements

| Package | Version | Why |
| --- | --- | --- |
| `react` | `^18.3.0` or `^19.0.0` | The hooks use `useSyncExternalStore`, `useTransition`, `useState`, `useRef`, `useEffect` and context — stable in both majors. |
| `@qubeejs/core` | `^1.3.0` | 1.3 adds `QubeeConfig.baseUrl` and the list layer — `defineList`, `readListState`, `buildListHref`, `buildListRequest` — that the adapter builds on. |

Type declarations ship with the package; there is no `@types/…` package to add.

## What you get

- **One entry point.** Every hook, the provider and their types come from `@qubeejs/react`.
- **ES modules and CommonJS**, with source maps and `sideEffects: false`.
- **Zero runtime dependencies.** React and the core are peers; nothing else is installed.
- **No `'use client'` directive.** The package works in any React app. In the Next.js App Router,
  import it only from files that start with `'use client'` — see
  [Vite / Next.js / React Router](/introduction/frameworks/).

## Keep the bundle small

Import the one driver you use — `STRAPI_DRIVER`, `LARAVEL_DRIVER` — rather than the `DRIVERS`
registry, so the other eighteen tree-shake out. The core docs measure the difference:
[Bundle size ↗](https://qubeejs.andreatantimonaco.me/guide/bundle-size/).

## Versions

`@qubeejs/react` follows [Semantic Versioning](https://semver.org/). Every release is listed in the
[changelog](/changelog/).
