## How it works

- **Every list stays in step.** All the components under the provider, and any that call
  `useBrowserAdapter()` themselves, see the same URL — through the Back and Forward buttons too.
- **It observes its own navigations, and Back and Forward.** A `pushState` by other code is not
  seen until the next `popstate`, so parameters that code added can be dropped by the next `set()`.
  When something else also writes the URL, that something is a router: use its adapter instead.
- **On the server it knows no URL.** A list renders its defaults there, and its real state right
  after hydrating. To render the right page on the server, use a router that knows the URL there —
  see [Server rendering](/guide/server-rendering/).
- **For one list that should not follow the provider**, pass `useBrowserAdapter()` as the second
  argument of `useQubeeList` — see [Adapters & providers](/guide/adapters/).
- **A router of your own** — hash routing, say — becomes a provider with
  [`createAdapterProvider`](/api/main/create-adapter-provider/).
