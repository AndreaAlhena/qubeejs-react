The adapter for TanStack Router ships with the package, as an entry point of its own:
`@qubeejs/react/tanstack-router`. It needs TanStack Router 1.49 or later, the first release whose
`navigate` takes an href. Wrap the root route's outlet in it once:

<Code code={tanStackRouterRoot} lang="tsx" title="src/routes/root.tsx" />

Every list under the root route then calls `useQubeeList(articleList)` and goes through TanStack
Router.

TanStack Router parses search params into typed objects of its own. A qubee list keeps its own URL
format, so the adapter reads the raw query string and writes whole hrefs through `router.navigate`.

## How it works

- It reads `location.searchStr`, the raw query string — `?q=react&sort=title` — and
  `location.pathname`.
- It navigates with `router.navigate({ href })`, which takes a fully built href and applies the
  router's basepath and rewrites, so the list's URL rules — defaults left out, foreign parameters
  kept — apply unchanged. TanStack's typed `navigate({ search })` would serialise a search object its
  own way instead.
- TanStack's default search serialiser re-types JSON-looking values (`?q=1.50` lands as `1.5`), so
  the list's state follows what the router wrote back: it settles, with no loop. Configure TanStack's
  `parseSearch` and `stringifySearch` to keep strings if that matters.
- If the route declares `validateSearch`, let it pass the list's keys through untouched: a validator
  that drops unknown keys drops the list's.
- For links, render `<a href={list.href(…)}>` with a plain-click handler, as the
  [Pagination bar](/recipes/pagination-bar/) does. Under a `basepath`, `list.href(…)` is the path
  inside it (TanStack strips the basepath from the location's pathname), so give the anchor
  `router.buildLocation({ href: list.href(…) }).publicHref`, which adds the basepath back.
- For the one list that should not follow the provider, pass `useTanStackRouterAdapter()` as the
  second argument — see [Adapters & providers](/guide/adapters/).
