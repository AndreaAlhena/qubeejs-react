## How it works

- `<ReactRouterAdapter>` goes **inside** the router — in the root route's component, around its
  `<Outlet />` — because it uses React Router's own hooks.
- It reads `useSearchParams()` and `useLocation()`, and navigates with `useNavigate()`. React
  Router's `navigate` may return a promise; the list does not wait for it.
- `<Link to={list.href(…)}>` navigates in place and keeps a real href, so no click handler is needed.
- A list navigation keeps the scroll position: where the app renders `<ScrollRestoration />`,
  React Router would otherwise scroll to the top on every sort, page or search.
  `<ReactRouterAdapter scroll>` — or `useReactRouterAdapter({ scroll: true })` — hands the reset
  back to React Router.
- Every component under the route reads the same URL, so each can call `useQubeeList(articleList)`.
  The draft and `isPending` stay with the component that made a change — see
  [Lists in the URL](/guide/url-lists/).
- For the one list that should not follow the provider, pass `useReactRouterAdapter()` as the second
  argument — see [Adapters & providers](/guide/adapters/).
- The entry needs `react-router` 7 or later. On React Router 6, write the adapter yourself — the
  same three hooks, imported from `'react-router-dom'` — and turn it into a provider with
  [`createAdapterProvider`](/api/functions/create-adapter-provider/).
