project is in the path, so it is the list's [input](/guide/list-input/). This recipe is for the
Next.js App Router, set up as in [Next.js](/setup/next/).

## The view, in the browser

<Code code={projectTasksView} lang="tsx" title="app/projects/[id]/tasks/project-tasks-view.tsx" />

A status button changes the query, never the path: Next.js renders the Server Component again
with the new `searchParams` and the same `params`. `list.request` carries the project too, if you
fetch in the browser instead.

## When the project is not known yet

When the path holds a slug and the API wants the project's id, the server awaits the lookup before
it builds the request. In the browser, pass `null` until the id is known: the list has no request,
and nothing is fetched.

<Code code={projectTasks} lang="tsx" title="src/projects/project-tasks.tsx" />

:::caution[Bee aware]
Declare the list in a module both sides import. It holds functions, so it can never travel from a
Server Component to a Client Component as a prop.
:::
